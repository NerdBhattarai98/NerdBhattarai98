<!-- ========== 4. PROBLEM SOLVING ========== -->
## Problem-Solving and Analytical Thinking

Technical tools matter, but the habits behind them matter more. These are the ways of working I value and am actively developing, and how each one shows up in my technical interests.

| Strength | How it connects to my work |
|---|---|
| **Analytical thinking** | Exploring a dataset with Pandas, asking what the numbers actually show, and visualizing patterns with Seaborn and Matplotlib before drawing conclusions. |
| **Logical reasoning** | Tracing how a program behaves step by step in Python, C, C++, and C#, including how data moves, where conditions branch, and why a result is produced. |
| **Breaking problems into steps** | Splitting a large task into small functions or components that can each be written, tested, and understood on their own. |
| **Problem-solving through code** | Turning a written problem into a working solution, then checking it against edge cases instead of stopping at the first version that runs. |
| **Interpreting and exploring data** | Cleaning and summarizing data with NumPy and Pandas, and questioning whether the data is complete and reliable before relying on it. |
| **Learning from mistakes** | Treating bugs and failed approaches as information: finding the root cause, fixing it, and applying the lesson to the next solution. |

**My general approach**

```text
Understand the problem  ->  Break it into smaller steps  ->  Implement one step at a time
        ->  Test and explore the results  ->  Reflect, refine, and document
```
